# Documentation rewrite: deepseek-harness removal and multi-repo analysis replacement

Two analysis documents (`docs/system-analysis.md` and `docs/architecture-reference-map.md`) were rewritten to replace all references to deepseek-harness and daily_agent with analysis drawn from 8 user-owned repositories: agent-dashboard, daily_rust, daily_mistral, llamaindex_daily, daily-digest-prompt, small_daily_tasks, AgentFlow-Notify, and RAG_Skill. The rewrite preserves the same structural purpose — mapping PEARL v2 components to existing reference patterns — while grounding every claim in code that actually exists in the user's repos. The architecture-reference-map grew from a deepseek-harness-heavy table to a 66-row matrix spanning 11 sections with explicit reuse-level classification.

Watch for: RAG_Skill appears in the reference list but contributes only 1 row (monorepo packaging) — it's borderline whether it belongs in the "8 reference projects" framing (possible). The fail-open characterization in the guard section could mislead readers about PEARL's intended posture (confirmed).

**Verdict**: APPROVED

---

## High-level view

The deepseek-harness removal is complete: zero occurrences of `deepseek-harness`, `deepseek_harness`, or `daily_agent` remain in either doc, verified by grep. Every file path cited in both documents was spot-checked against the actual repo contents and confirmed to exist with the expected symbols. The spec doc (`系統開發需求書.md`) retains DeepSeek Harness mentions as architectural non-goals — intentional and correct per the task requirements.

The architecture-reference-map covers 66 rows: 24 direct-port, 30 adapt, 7 reference-only, 5 new-build. The gap analysis correctly identifies what no reference covers (Precision Decision Engine, Plan Compiler, Assurance Engine, Durable Queue, Repair Transaction). The system-analysis doc has some redundancy with the architecture-reference-map since both describe the same patterns — acceptable given they serve different reading patterns (narrative vs. lookup table).
